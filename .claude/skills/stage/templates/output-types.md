# 단계별 최종 문서 유형

`doc` 모드는 이 파일에서 단계 번호(NN) 행을 찾아 문서 유형, 파일 이름, 장 구성을 정한다. 공통 골격(머리 표, 1장 개요, 요구사항 추적표, 부록)은 [output.md](output.md)에 있다. 아래 장 목록은 2장부터의 본문이다.

- "참고 구조"는 장을 고를 때 참고한 표준 양식이다. 경량판으로 줄여 쓰고, 원본의 모든 절을 따르지는 않는다.
- 01~04의 장 구성은 이 프로젝트의 확정 문서에서 가져왔다. 05 이후는 아직 쓰인 예가 없는 초기안이다. 처음 쓸 때 사용자와 장 구성을 확인하고, 확정되면 이 파일을 고친다.
- (선택) 장은 내용이 없으면 뺀다. 그 밖의 장이 이 단계에 해당하지 않으면 제목을 남기고 "해당 없음"과 이유를 한 줄로 적는다.
- 장 안의 절은 내용에 맞게 나눈다. 아래 "내용" 열은 들어가야 할 것이다.
- 도메인 고유의 요구사항 영역(예: 출제 범위, 근거·검증)은 장을 더해도 된다. 더한 장은 1.5 표기에 ID 접두어를 적는다.

## 공통 ID 접두어

| 접두어 | 뜻 | 처음 매기는 단계 | 형식 |
| --- | --- | --- | --- |
| `C` | 제약 | 01 | `C-1` |
| `FR` | 기능 요구사항 | 01 | 영역 `FR-1`, 개별 `FR-1.2` |
| `NFR` | 비기능 요구사항 | 01 | 영역 `NFR-1`, 개별 `NFR-1.2` |
| `D` | 설계 결정 | 02 | `D-1` |
| `QS` | 품질 시나리오 | 02 | `QS-1` |
| `EXP` | 실험 | 04 | `EXP-1` |
| `F` | 리뷰 발견 사항 | 05 | `F-1` |
| `TC` | 테스트 케이스 | 06 | `TC-1` |
| `DEF` | 결함 | 06 | `DEF-1` |

## 01 요구사항 정의서

- 파일: `requirements.md`
- 참고 구조: ISO/IEC/IEEE 29148 SRS 경량판
- 1장: 목적, 제품 목표(인용 블록 한 문장), 범위, 용어, 표기, 참고 문서를 모두 둔다.
- 1.5 표기에 반드시 둘 것: 요구사항 ID 형식, 우선순위 값(예: 필수, 축소 대상)의 정의, 검증 방법 값(테스트, 시연, 검사, 분석)의 정의

| 장 | 내용 |
| --- | --- |
| 전체 설명 | 사용자, 운영 환경, 제약(`ID \| 제약` 표, `C-n`). 가정과 의존이 있으면 절을 더한다 |
| 기능 요구사항 | 영역마다 `### FR-n <영역 이름>` 절과 표 하나. 행은 `ID \| 요구사항 \| 우선순위 \| 검증` |
| 비기능 요구사항 | 영역마다 `### NFR-n` 절. 행 형식은 기능 요구사항과 같다. 스택·환경·모델처럼 선택을 기록하는 영역은 `ID \| 구성 \| 선택 \| 비고`처럼 열을 바꿔도 된다 |
| 품질 지표와 완료 조건 | 완료 조건(번호 붙은 조건 표), 판정 기준과 미달 처리, 기준선 지표(`지표 \| 내용`) |

- 부록 A 범위 밖 항목을 둔다.

## 02 설계서

- 파일: `design.md`
- 참고 구조: arc42, IEEE 1016 경량판
- 1장: 목적, 설계 목표(`목표 \| 관련 요구사항`), 용어(더하는 것만), 다음 단계에서 확인할 항목을 둔다.
- 그림은 mermaid로 그린다. 그림의 요소 이름은 본문 표의 이름과 같게 쓴다.
- 결정은 본문에 결과만 쓰고 "(D-n)"으로 설계 결정 장을 가리킨다.

| 장 | 내용 |
| --- | --- |
| 아키텍처 | 개요(경로나 계층 구분, 외부 시스템까지 포함한 그림), 프로세스(`프로세스 \| 시작 \| 수명 \| 외부 접근`) |
| 기술 스택과 설정 | 기술 스택(`구성 요소 \| 선택 \| 버전·고정 방식 \| 근거`, 근거는 요구 ID), 설정과 포트(`항목 \| 값 \| 쓰는 곳`) |
| 모듈 설계 | 코드 구조(디렉토리 트리), 모듈 책임과 경계(`모듈 \| 책임 \| 의존 \| 하지 않는 것`), 모듈별 규칙 |
| 데이터 설계 | 스키마, 식별자와 값 규칙(`대상 \| 규칙`), 상태 전이(`stateDiagram`), 저장소 파일(`파일 \| 내용 \| 만드는 곳`) |
| 주요 흐름 | 흐름마다 절 하나(관련 요구 ID를 제목에). 그림, 단계·노드 표(`입력 \| 출력 \| 실패 이유`), 판정 규칙. 실패와 재시도 경로를 포함한다 |
| 인터페이스 | API(`메서드 \| 경로 \| 동작 \| 요구사항`), CLI(`명령 \| 동작`) |
| 횡단 관심사 | 외부 호출(타임아웃, 재시도, 동시성, 비용), 격리, 관측, 마이그레이션과 백업, 보안, 거절 규칙 |
| 설계 결정 | `ID \| 결정 \| 검토한 대안 \| 이유 \| 상세`. 이유나 대안이 기록에 없으면 "-"로 둔다. 지어내지 않는다 |
| 품질 시나리오 (선택) | `ID(QS-n) \| 품질 속성 \| 자극 \| 기대 반응 \| 측정 \| 관련 요구 ID`. 비기능 요구사항을 확인 가능한 시나리오로 바꾼다 |
| 위험과 기술 부채 (선택) | `위험 \| 영향 \| 대응 \| 관련 D-n`. 설계가 알고 받아들인 위험과 미룬 작업 |

- 다음 단계 작업 분해와 개발 도구·모델 권고는 이 문서에 넣지 않는다. 기록 파일로 옮긴다.

## 03 구현 결과서

- 파일: `implementation.md`
- 코드는 `docs/` 밖에 있다. 이 문서는 경로와 검증 결과만 적는다.
- 장 구성은 이 프로젝트의 확정 문서(2026-11-05, 1.0)에서 가져왔다.
- 1.4에는 더하는 용어 표 아래에 제품 고유의 구성 개념(관계 도식과 표)을 둘 수 있다. 상위 문서의 용어를 모으되 뜻을 바꾸지 않는다.
- 요구사항 추적표는 `요구사항 \| 설계 위치 \| 구현 경로 \| 검증`이다. 설계서의 설계 결정(D-n)마다 구현 위치와 상태를 적는 절을 더한다.

| 장 | 내용 |
| --- | --- |
| 구현 범위 | `작업 단위 \| 상태(완료, 부분, 제외) \| 산출 경로 \| 비고`. 작업 단위는 03 계획의 것을 쓴다 |
| 실제 코드 구조 | 설계서 모듈 설계와 대조한 경로 |
| 빌드와 실행 | 준비 명령, 명령, 운영 순서(mermaid), 환경 변수, lock 파일 위치와 고정 버전 |
| 설계 대비 변경 | `설계 위치 \| 설계 \| 구현 \| 이유 \| 설계서 개정`. 개정 값은 `반영(n.0)`, `필요`, `불필요` |
| 테스트 결과 | 실행 명령, 테스트 수, 통과·실패, 측정한 경우 커버리지. 자동 테스트로 못 본 것(실제 모델, 브라우저)은 확인 방법과 결과를 표로 |
| 완료 조건 판정 | 요구사항 완료 조건(`# \| 조건 \| 결과 \| 판정`), Seed 수용 기준(`번호 \| 기준 \| 증거 \| 판정`), 기준선 지표 값. 측정 쿼리는 관련 산출물로 링크한다 |
| 알려진 문제와 기술 부채 | `문제 \| 영향 \| 처리 단계` |

## 04 실험 보고서

- 파일: `experiments.md`
- 장 구성은 이 프로젝트의 확정 문서(2026-11-05, 1.0)에서 가져왔다. 실험마다 장 하나로 묶어 한 실험을 끝까지 따라 읽게 한다.
- 1장 앞에 "쉬운 설명" 절을 둔다. 실험마다 `실험 \| 물은 것 \| 결과 \| 결정`을 한 줄씩 쓴다.
- 1장에 출발점(이전 단계 기준선, `문제 \| 기준선 값 \| 실험`)을 둔다.
- 실험 장마다 흐름도(mermaid)를 하나 둔다.
- 요구사항 추적표는 `요구사항 \| 이 문서 위치 \| 관계`다. 설계 결정(D-n)마다 같은 형식의 절을 더한다.

| 장 | 내용 |
| --- | --- |
| 실험 목표와 가설 | `EXP-n \| 질문 \| 가설 \| 관련 요구 ID` |
| `EXP-n <실험 이름>` (실험마다 한 장) | 설계: 변형(프롬프트, 모델, 그래프 구조), arm과 고정 조건, 데이터셋, 지표, 판정 기준(고정 시점 포함). 결과: arm별 지표값, 비용, 시간, 원자료 위치. 결정: 고정 기준 판정, 결정(채택, 보류, 기각), 이유. 타당성 위협: `위협 \| 내용 \| 결과에 미치는 방향 \| 보완안`(표본 크기, 평가 누수, 재현성) |
| 결정 요약과 설계서 반영 | 실험별 결정과 운영 반영 위치. 실험용으로 더한 기능과 설계서 위치. 설계서·요구사항 개정 여부 |
| 재현 방법 | 고정 값(시드, 데이터셋 해시, 프롬프트, 모델, 리전, 단가), 실험별 명령 |

- 부록 A 범위 밖 항목에 하지 않은 실험 후보와 다시 할 실험을 둔다.
