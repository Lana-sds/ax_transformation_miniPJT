# EXP-2 결과: 생성 프롬프트의 인용 복사

상태: 확정
작성일: 2026-11-05

## 쉬운 설명

문제를 만드는 AI는 근거로 공식 문서 문장을 그대로 베껴 와야 한다. 03 단계에서는 이 베끼기가 자주 틀려서 문제를 다시 만들었다. 다시 만들 때마다 시간과 돈이 더 든다.

- 같은 6개 주제로 원래 지시문(`control`)과 새 지시문(`arena`)이 각각 문제를 만들게 했다. 새 지시문은 "링크와 코드 펜스 첫 줄까지 원문 그대로 베끼고, 다 쓴 뒤 원문과 대조하라"는 지시를 더했다.
- 결론: 새 지시문은 첫 시도에서 6개 중 5개를 맞게 베꼈다. 원래 지시문은 2개였다. 다시 만든 횟수가 6번에서 1번으로 줄었다. 문제당 비용은 0.39달러에서 0.23달러로 내려갔다. 두 쪽 모두 6문제를 다 통과시켰다. 미리 정한 기준으로 채택 후보다.
- 하지만 주제가 6개뿐이라 방향만 본다.

## 4. 판정

판정 기준은 실행 전에 고정했다(계획 4단계).

| 기준 | `control` | `arena` | 충족 |
| --- | --- | --- | --- |
| 첫 시도 `quote_match` 비율이 더 높다 | 0.33 | 0.83 | 예 |
| passed 수가 같거나 많다 | 6 | 6 | 예 |
| passed당 비용이 같거나 낮다 | 0.388 | 0.231 | 예 |
| 기각 조건: Judge 통과율이 나빠진다 | 0.917 | 1.000 | 아니오 |
| 기각 조건: T2.11 실패가 늘었다 | 0 | 0 | 아니오 |

판정: `arena` 생성 프롬프트는 채택 후보다.

판정을 읽을 때 볼 점:

- 슬롯이 6개다. 첫 시도 차이는 3슬롯(2, 3, 6번)이다. 반복 실행이 없어서 같은 설정에서 생기는 흔들림과 구별하지 못한다.
- 03 기준선의 첫 시도 `quote_match`는 93/209(0.44)다. 이번 `control` 0.33은 그보다 낮다. 표본이 작아서 기준선과 직접 비교하지 않는다.
- 비용 차이는 재생성이 줄어서 생겼다. 슬롯마다 근거 문서 길이가 달라 시도당 토큰은 슬롯마다 다르다. 두 arm이 같은 슬롯을 돌았으므로 합끼리 비교한다.
- Judge는 두 arm 모두 `control` 프롬프트다. EXP-1 결과와 섞지 않았다.
- 채택 여부는 5단계 누수 점검 뒤 사용자가 정한다.
