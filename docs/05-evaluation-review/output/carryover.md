## 2. Judge 입력 비교(항목 1)

EXP-1 문항 77개 중 DB 출처 53개를 운영 판정 때 입력과 비교했다. 인라인 출처 24개(결함 주입 사본)는 운영 입력이 없다.

| 차이 | 문항 수 | 내용 |
| --- | --- | --- |
| Judge 프롬프트 | 2 | 배치 `b20261105-01`(00:32Z 시작)은 Judge 프롬프트 마지막 변경(`f0b5583`, 02:10Z) 전에 판정됐다 |
| 근거 페이지 | 14 | 허용 목록에 27행을 더한 커밋(`05f9b58`, 04:03Z) 전에 시작한 배치다. 그때 허용 목록으로 계산한 슬롯 페이지 수와 지금 수가 다르다(예: 3개 → 9개). 실험은 지금 허용 목록으로 다시 계산했다 |
| 단답 허용 답안 | 2 | DB 값에 Judge가 보탠 변형(`missing_variants`)이 합쳐져 있다. 운영 Judge는 합치기 전 값을 봤다 |

결론: 03 운영 판정을 `control-s45`의 반복 실행 하나로 볼 수 있는 문항은 38개다. 근거 페이지 차이는 배치 시작 시각으로 추정했다. 재개(`--resume`)로 04:03Z 뒤에 판정된 슬롯이 있으면 차이가 더 적다(미확인).

| --- | --- |
| 명령 | `QUIZ_DB=data/experiments/EXP-2/arena.db uv run quiz crosscheck --batch b20261105-01` |
| 결과 파일 | `data/experiments/EXP-2/crosscheck-arena.json`, `.md` |
| 운영 파일 보호 | 같은 이름 `data/crosscheck/b20261105-01.*`을 먼저 복사해 두고, 실행 뒤 결과를 옮기고 되돌렸다. `git diff data/crosscheck/` 0줄 |

| 근거 문장과 저장 인용 | 같음 3회, 포함 관계 6회, 겹침 0.16 1회(gpt-oss-120b, `b20261105-01-006`) |
| 비용 | 미확인. 교차 풀이는 토큰 수를 기록하지 않고 단가표에 두 모델이 없다. 호출 10회 |

풀이자는 인용이 아니라 페이지 전체를 본다. 그래서 정답 일치만으로는 "인용이 정답을 뒷받침한다"고 말할 수 없다. 근거 문장이 저장 인용과 같거나 포함 관계인 9회가 그 주장의 근거다. 6문항은 비율이 아니라 개수로 본다.

## 4. `version_conflict` 4문항(항목 7)

| 문항 | 문서 | 지금 실행 | 판단 |
| --- | --- | --- | --- |
| `b20261105-03-016` | `graph-api-control-flow` | 보기 A만 기대값보다 한 단계 일찍 `Recursion Error`. Judge 예측은 기대값과 같다 | 원인 미확인(재귀 한도 세는 방식 차이로 보임) |
| `b20261105-03-024` | `ToolNode` API 레퍼런스 | 보기 4개 모두 `ValueError`가 전파된다. 기대값과 Judge 예측은 `ToolMessage`로 잡힌다고 했다 | 스냅샷 원문은 기본값이 "tool execution errors는 다시 던진다"다. 실행 결과가 문서와 맞다. 생성 기대값과 Judge 예측이 함께 틀렸다 |
| `b20261105-03-034` | `middleware/custom` | 보기 B가 기대값(`AttributeError`)과 달리 정상 종료 | 원인 미확인 |
| `b20261105-03-036` | `short-term-memory` | 보기 D가 기대값과 달리 `ValueError` | 원인 미확인 |

`03-024`는 판정 규칙의 빈틈을 보여 준다. 규칙은 "실행만 기대값과 다르고 Judge 예측은 기대값과 같으면 `version_conflict`"다. 생성 모델과 Judge가 같은 오해를 하면 이 규칙은 라이브러리 버전 문제로 분류한다. 샌드박스 버전은 `langgraph` 1.2.19, `langgraph-prebuilt` 1.1.1이다.
