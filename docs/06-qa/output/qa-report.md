이 문서는 웹 화면을 실제 브라우저로 시험한 결과다. 판정 기준은 요구사항 정의서다. 05 발견과 같은 결함은 05 ID(F-n)로 함께 추적한다.

## 쉬운 설명

사용자처럼 브라우저에서 문제를 풀어 보며 화면을 시험했다. 시험 시나리오는 17개다. 세트 시작, 형식 4개 풀이, 오답 태그, 복습, 새 문제 소진, 감사 화면, 휴대폰 폭, 연속 클릭, 다른 곳에서 세트를 새로 만든 경우가 들어 있다.

- **찾은 결함**: 7개다. 화면 코드로 고칠 수 있는 6개를 고쳤다. 정답이 A에 몰린 1개(DEF-6, 05의 F-20)는 서버와 문제 생성을 바꿔야 해서 기록만 했다.
- **고친 것**: 버튼 두 번 누르기 오류, 닫힌 세트에 화면이 묶이는 문제, "세트 1를" 같은 조사 오류, 별표(`**`)가 그대로 보이는 문제, 휴대폰 폭에서 화면이 옆으로 밀리는 문제, 구절 표에 마크다운 기호가 보이는 문제다.
- **더한 것**: "세트 N"과 "감사"에 설명 말풍선을 붙였다.
- **점수**: 화면 건강 점수가 90에서 98로 올랐다. 남은 감점은 DEF-6이다.
- **데이터**: 시험은 시험 전용 DB에서 했다. 제출한 `data/quiz.db`는 바뀌지 않았다.

판정: 조건부 출시 가능하다. 조건은 7장에 있다.

이 문서를 읽는 데 필요한 말:

| 말 | 뜻 |
| --- | --- |
| TC | 시험 시나리오 하나 |
| DEF | 시험에서 찾은 결함 하나 |
| 세트 | 한 번에 푸는 문제 10개 묶음 |
| 닫힌 세트 | 더 새 세트가 시작돼 답을 받지 않는 세트 |
| 건강 점수 | 화면 품질을 0~100으로 매긴 값. 범주별 점수를 가중 평균한다(2.4) |
| 회귀 테스트 | 고친 결함이 다시 생기면 실패하는 자동 테스트 |

## 1. 개요

### 1.1 목적

이 문서는 MVP 웹 화면의 시험 범위, 시나리오 결과, 결함, 지표, 출시 판정을 정의한다.

### 1.2 단계 목표

| 목표 | 관련 요구사항 |
| --- | --- |
| 풀이 흐름 전체를 실제 브라우저에서 시험한다 | FR-1~FR-5, FR-8, FR-9 |
| 화면 결함을 재현하고 고친 뒤 같은 절차로 다시 확인한다 | FR-1~FR-5 |
| 제출 DB를 바꾸지 않는다 | C-1, evaluation.md 6.2 |

### 1.3 범위

- 웹 화면(`web/`)과 그 화면이 부르는 API다.
- 문제 생성, 교차 풀이, 샌드박스는 시험하지 않았다(05에서 평가).
- 범위 밖 항목은 부록 A에 있다.

### 1.4 용어 정의

요구사항 정의서와 평가·리뷰 보고서 1.4의 용어를 그대로 쓴다. 이 문서에서 더하는 용어는 "쉬운 설명"의 표에 있다.

### 1.5 표기

- ID 체계: `TC-n`은 시험 시나리오, `DEF-n`은 결함이다.
- 심각도(05 기준표): 높음은 요구사항·고정 결정 위반, 중간은 기능이 틀리지만 우회할 수 있음, 낮음은 문서·가독성 문제다.
- 결함 범주와 건강 점수 심각도: critical, high, medium, low. high는 핵심 작업이 우회 없이 막힘, medium은 우회가 있음, low는 겉모양 문제다.
- 결과 값: 통과, 실패, 기록(측정만 하고 판정 대상이 아님).

### 2.4 건강 점수 계산

범주 8개(Console 15%, Links 10%, Visual 10%, Functional 20%, UX 15%, Performance 10%, Content 5%, Accessibility 15%)의 가중 평균이다. 범주 점수는 100에서 결함마다 뺀다(critical 25, high 15, medium 8, low 3). Console은 오류 수, Links는 깨진 링크 수로 매긴다. 시험하지 않은 범주(Performance, Accessibility)는 빼고 남은 가중치로 나눈다. 그래서 이 문서의 점수는 잠정값이다.
