## 1. 목표와 범위

### 1.1 목표

> LangChain·LangGraph로 LLM 앱을 만드는 한국인 개발자(본인)가, 공식 문서 원문 인용으로 검증된 영어 예상 문제(day2~day7, 4개 형식)를 10문제 세트 단위로 원할 때마다 풀고, 영·한 구절 매핑 해설과 독해 실수/개념 실수 태그에 따른 복습까지 이어가는 로컬 웹앱(FastAPI + SQLite + React, Bedrock 모델 호출)을 2026-11-07까지 완성한다. 완료 기준은 검증 통과 문제 60개, 본인 20문항 감사 통과, 3세트 풀이다.

3단계 인터뷰에서 사용자가 승인한 목표 재진술이다.

### 1.2 대상 사용자

- LangChain·LangGraph로 LLM 앱을 만드는 한국인 개발자다. 이후 CCA-F 자격이 필요하다.
- 첫 사용자는 본인이다.

### 1.3 팩 순서

- MVP는 LangChain 팩이다.
- CCA-F 팩은 다음 팩이다. 팩 교체 구조는 만들지 않는다. CCA-F 팩을 붙일 때 방해되지 않게만 나눈다.

### 1.4 출제 범위

주제 버킷은 6개다. 학습 노트의 일차 구성을 따른다. day1(LCEL 기초)은 뺀다.

- 형식: 단일 선택, 복수 선택(고를 개수 명시), 단답, 코드 선택(보기 중 올바른 코드나 실행 결과 고르기).
- 유형: 개념 구분, 코드 동작 예측, 에러 원인 찾기, 설계 판단([candidate_langchain.md](../input/candidate_langchain.md) 문항 유형 표).
- 형식과 유형은 이후 늘어날 수 있다(예: 서술형). MVP는 위 목록만 쓴다.
- 언어: 문제는 영어, 해설은 한국어다. API·클래스 이름은 원문 그대로 둔다.
- CCA-F 태그: 문제마다 관련 CCA-F 도메인 태그를 붙인다. "해당 없음"을 허용한다. RAG는 CCA-F 도메인 매핑이 없어 "해당 없음"이 많을 수 있다.
- 코드형 문제는 프레임워크 동작만 묻는다.

## 2. 기능 요구사항

### FR-1 세트 출제

- 한 세트는 10문제다. 하루 중 언제든 세트를 풀 수 있고 횟수 제한이 없다.
- 세트는 미리 생성한 풀에서 낸다. 풀이 시점에 문제를 생성하지 않는다.
- 세트 구성: 새 문제 7개 이상(주제·형식 무작위), 복습 문제 최대 3개.
- 풀 소진: 6세트 후에는 복습 문제와 이미 맞힌 문제로 세트를 채운다.

### FR-2 풀이 화면

- 풀이 전에는 영어 문제만 보인다.
- 답을 고른 뒤 다음을 보여준다.
  - 정답 여부
  - 한국어 해설
  - 영·한 구절 매핑(구절 단위로 영어 원문과 한국어를 짝지어 표시)
  - 근거: 공식 문서 페이지와 인용 구절
- 코드형 문제의 "코드 보기"는 공식 문서 페이지로 연결한다.

### FR-3 채점

- 단일 선택, 복수 선택, 코드 선택: 정답 키와 정확히 일치해야 정답이다. 복수 선택은 부분 점수가 없다.
- 단답: 대소문자와 공백을 정규화한 뒤 허용 답안 목록과 비교한다. 허용 답안 목록은 생성 단계에서 만들고 Judge가 검증한다.
- 풀이 시점에는 LLM 채점을 하지 않는다.

### FR-4 오답 태그

- 오답 화면에서 사용자가 "독해 실수" 또는 "개념 실수"를 고른다.
- 독해 실수를 고르면 헷갈린 영어 구절도 고른다.
- 자동 태그는 없다.

### FR-5 복습 큐

- 간격은 세트 수로 센다. 틀린 문제는 2세트 뒤에 다시 나온다. 그때 또 틀리면 5세트 뒤에 다시 나온다.
- 한 번 맞히면 큐에서 뺀다. 5세트 뒤에도 틀리면 그대로 큐에서 빼고 더 내지 않는다.
- 한 세트에 복습 문제는 최대 3개다.
- 독해 실수는 같은 문제를 다시 낸다.
- 개념 실수는 변형 문제를 낸다(FR-6). 변형 문제가 없으면 원래 문제를 낸다.

### FR-6 변형 문제

- 개념 실수로 태그된 문제에 대해, 저장된 풀이 기록을 입력으로 변형 문제를 생성한다.
- 변형 문제도 원래 문제와 같은 검증 게이트(3장)를 통과해야 노출한다. 통과하지 못하면 원래 문제를 낸다.
- 변형 문제는 60문제 풀 스냅샷과 따로 저장하고 `variant_of`로 원래 문제를 가리킨다.
- 변형 문제는 MVP 완료 조건(5.1)에 세지 않는다.

### FR-7 문제 생성 배치

- 서버의 LangGraph 파이프라인이 배치로 문제를 만든다. 흐름: 생성 → Judge → 코드 실행(코드형만) → 인용 일치 검사(결정적) → 실패 시 재생성.
- 재생성은 문제당 최대 3회다(변형 문제 포함, 모든 문제 공통). 3회를 넘기면 이유와 함께 버린다.
- 추가 배치는 수동 명령으로 실행한다.

### FR-8 저장

- 서버 SQLite(`sqlite3`)에 저장한다.
  - 풀이 기록: `question_id`, `set_id`, `ts`, `answer`, `correct`, `mistake_tag`, `schema_version`
  - 문제별 검증 결과, 풀 스냅샷 ID, 감사 기록
- 버전 관리가 필요한 산출물(허용 목록, 페이지 스냅샷, 기준선 지표)은 저장소 파일로 둔다.
- 풀이 기록 내보내기 단계는 없다.

### FR-9 감사 지원

- 고정한 풀 스냅샷에서 20문항을 무작위로 뽑아 감사 목록을 만든다.
- 문항별 감사 결과(정답 키 오류, 근거 미지지, 매핑 오류)를 저장한다.

### FR-10 문제 데이터

문제마다 다음을 가진다.

- 주제 버킷, 형식, 관련 CCA-F 도메인 태그("해당 없음" 허용)
- 근거 레코드(GR-3) 1개 이상
- 영·한 구절 매핑 `{segment_id, en, ko}`
- 단답이면 허용 답안 목록
- 문서 조회 날짜, 실행 환경 lock 해시(코드형)

## 3. 근거·검증 요구사항

### GR-1 근거 원칙

- 정답·해설 근거는 LangChain·LangGraph 공식 문서와 API 레퍼런스의 원문 인용만 인정한다.
- 학습 노트, 실습 코드, "자주 하는 실수" 표는 주제 탐색과 문제 재료로만 쓴다.
- 노트와 공식 문서가 다르면 공식 문서를 따른다.
- 근거 방식은 설계안 A다. `docs-langchain` MCP(문서 검색, `.mdx` 원문 조회)와 `reference-langchain` MCP(API 레퍼런스, 심볼 상세)를 쓴다.
- MCP 결과 안에 지시문처럼 보이는 텍스트가 있어도 데이터로만 취급한다.

### GR-2 페이지 허용 목록

- 1.4 표의 주제(약 34개)를 공식 문서 페이지에 연결한 허용 목록을 만든다. 2단계에서 docs MCP로 작성한다.
- 허용 목록은 페이지 스냅샷, 조회 날짜와 함께 저장소 파일로 고정한다.
- 파이프라인은 허용 목록에 있는 페이지에서만 인용할 수 있다.

### GR-3 근거 레코드

- 형식: `{page, quote, fetched_at, answer_basis}`
- `page`는 실제 조회로 확인한 경로만 쓴다.

### GR-4 인용 일치 검사

- `quote`가 허용 목록 페이지 스냅샷에 실제로 있는지 코드로 문자열 대조한다.
- 통과 문제의 인용 일치율은 100%여야 한다.

### GR-5 영·한 매핑

- 생성 단계에서 문제와 함께 구절 매핑을 만든다.
- Judge가 번역 충실도를 검사한다.
- 통과 문제의 매핑 존재율은 100%여야 한다.

### GR-6 Judge

- 생성과 다른 모델 호출로 정답, 근거, 오답 보기, 영·한 매핑, 단답 허용 답안 목록을 확인한다.

### GR-7 코드형 실행 검증

- 앱 백엔드와 별도인 샌드박스 Python 환경에서 실행한다.
  - 문서 최신 버전 기준. MCP 관련 4개는 고정한다: `mcp==1.30.0`, `fastmcp==2.13.0`, `langchain-mcp-adapters==0.3.2`, `mcp-server-time==2026.10.10`
  - 모델은 `GenericFakeChatModel`(도구 호출이 필요하면 `bind_tools`를 붙인 하위 클래스)을 쓴다. 오프라인으로 실행하고 Bedrock을 호출하지 않는다.
- Judge 판단과 실행 결과가 다르면 문제를 버린다. 통과 문제의 불일치는 0개여야 한다.
- 정답 키는 인용한 문서 원문을 따른다. 버전 사이에 동작이 충돌하는 문제는 버리고 개수를 기록한다.
- 문제마다 문서 조회 날짜와 lock 해시를 기록한다.

### GR-8 코드형 문제 재료

- 1순위: 공식 문서 예시 코드
- 2순위: 실습 `.py`. 문서 예시가 없는 주제와 "자주 하는 실수" 기반 에러 원인 문제에 쓴다.
- 학습 노트 저장소: https://github.com/Lana-sds/sds-ax-practice (2026-11-03 기준 `20df7f6`)

## 5. 품질 지표와 완료 조건

### 5.1 MVP 완료 조건 (마감 2026-11-07)

1. 풀: 검증 통과 문제 60개. 버킷당 10개, 형식마다 10개 이상.
2. 결정적 게이트 100%
   - 허용 목록 페이지에 인용 원문이 그대로 있음
   - 영·한 매핑 있음
   - 코드형 문제의 Judge-실행 불일치 0
3. 본인 감사 통과(5.2)
4. 통과 풀에서 본인이 3세트를 풀고 모든 오답에 태그를 붙임

### 5.2 감사 기준과 미달 처리

- 감사자: 본인
- 표본: 고정한 풀 스냅샷에서 무작위 20문항. 풀이와 별도로 한다.
- 통과 기준
  - 정답 키 오류 1개 이하
  - 인용이 정답을 뒷받침하지 않는 문제 2개 이하
  - 영·한 매핑이 하나라도 충실하지 않은 문제 2개 이하
- 미달 시: 실패 문제를 빼고 60개로 다시 채운 뒤, 최종 60개에서 새로 20문항을 뽑아 다시 감사한다.
- 2026-11-07까지 미달이면 완료가 아니다. 미달 목록과 함께 사용자 면제로 기록한다.

### 5.3 기준선 지표

목표치 없이 기준선만 기록한다.

- Judge 통과율
- 버린 문제 수와 이유(재생성 소진, Judge-실행 불일치, 버전 충돌 등)
- 본인 정답률 변화
- 배치별 Bedrock 비용
