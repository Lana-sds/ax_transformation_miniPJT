## 1. 개요

### 1.1 목적

이 문서는 LangChain 예상 문제 풀이 웹앱 MVP가 갖춰야 할 기능, 근거 검증, 비기능 요구사항과 완료 조건을 정의한다. 설계와 구현은 이 문서를 기준으로 한다.

### 1.2 제품 목표

> LangChain·LangGraph로 LLM 앱을 만드는 한국인 개발자(본인)가, 공식 문서 원문 인용으로 검증된 영어 예상 문제(day2~day7, 4개 형식)를 10문제 세트 단위로 원할 때마다 풀고, 영·한 구절 매핑 해설과 독해 실수/개념 실수 태그에 따른 복습까지 이어가는 로컬 웹앱(FastAPI + SQLite + React, Bedrock 모델 호출)을 2026-11-06 17:00까지 완성한다. 완료 기준은 검증 통과 문제 60개, 본인 20문항 감사 통과, 3세트 풀이다.

### 1.3 범위

- MVP는 LangChain 팩 하나다. 출제 범위는 3장을 따른다.
- CCA-F 팩은 다음 팩이다. 팩 교체 구조는 만들지 않는다. CCA-F 팩을 붙일 때 방해되지 않게만 나눈다.
- MVP에 넣지 않는 항목은 부록 A에 있다.

### 1.4 용어 정의

| 용어 | 뜻 |
| --- | --- |
| 팩 | 한 시험·학습 영역의 문제 풀과 그 근거 자료 묶음. MVP는 LangChain 팩이다 |
| CCA-F | LangChain 팩 다음에 붙일 자격 시험 팩. 문제마다 관련 도메인 태그를 단다(CR-7) |
| 버킷 | 출제 주제 묶음. 학습 노트의 일차(day2~day7)와 1:1로 대응한다(CR-1) |
| 형식 | 답하는 방식. 단일 선택, 복수 선택, 단답, 코드 선택(CR-3) |
| 유형 | 묻는 내용의 종류. 개념 구분, 코드 동작 예측, 에러 원인 찾기, 설계 판단(CR-4) |
| 코드형 문제 | 코드 선택 형식 문제. 보기 코드를 실행해 검증한다(GR-7) |
| 풀 | 미리 생성해 검증을 통과한 문제 집합 |
| 풀 스냅샷 | 특정 시점의 풀을 고정한 것. 세트 출제와 감사의 기준이다 |
| 세트 | 한 번에 푸는 10문제 묶음 |
| 복습 큐 | 틀린 문제를 정해진 세트 간격 뒤에 다시 내기 위한 대기 목록 |
| 변형 문제 | 개념 실수로 틀린 문제의 같은 개념을 다르게 묻는 새 문제(FR-6) |
| 독해 실수 / 개념 실수 | 사용자가 오답에 붙이는 두 가지 원인 태그(FR-4) |
| 허용 목록 | 인용해도 되는 공식 문서·API 레퍼런스 페이지 목록(GR-2) |
| 페이지 스냅샷 | 허용 목록 페이지의 원문을 조회 날짜와 함께 저장한 파일 |
| 근거 레코드 | 정답 근거 한 건. `{page, quote, fetched_at, answer_basis}`(GR-3) |
| 영·한 구절 매핑 | 영어 문제를 구절로 나눠 각 구절에 한국어를 짝지은 것. `{segment_id, en, ko}` |
| Judge | 생성과 다른 모델 호출로 문제를 검토하는 단계(GR-6) |
| 결정적 게이트 | 모델 없이 코드로 판정하는 검사. 인용 일치, 매핑 존재, 코드형 Judge-실행 일치 |
| 감사 | 본인이 풀 스냅샷 표본 20문항을 직접 검토하는 것(7.2) |
| 샌드박스 | 코드형 문제를 실행하는 앱과 분리된 Python 환경 |
| lock 해시 | 샌드박스 패키지 lock 파일의 해시. 실행 환경을 식별한다 |

### 1.5 표기

- 요구사항 ID: `CR` 출제 범위, `FR` 기능, `GR` 근거·검증, `NFR` 비기능. `FR-1.2`는 FR-1 영역의 두 번째 요구사항이다.
- 우선순위
  - 필수: MVP 완료에 필요하다.
  - 축소 대상: 일정이 부족하면 뺄 수 있다. 축소 판단 기준과 순서는 프로젝트 계획에서 관리한다([05-output.md](../../dev-process/01-requirements/05-output.md) A.3).
- 검증 방법: 테스트(자동 테스트), 시연(화면에서 확인), 검사(코드·데이터·문서 확인), 분석(지표·기록 분석)

## 2. 전체 설명

### 2.1 사용자

- LangChain·LangGraph로 LLM 앱을 만드는 한국인 개발자다. 이후 CCA-F 자격이 필요하다.
- 첫 사용자는 본인이다.

### 2.2 운영 환경

- 개발자 PC에서 로컬로 돈다(NFR-1).
- 문제 생성은 개발자가 수동으로 돌리는 배치다. 풀이 시점에는 모델을 부르지 않는다(FR-1.3, FR-3.4).
- 모델 호출은 AWS Bedrock을 거친다(NFR-2, NFR-4).

### 2.3 제약

| ID | 제약 |
| --- | --- |
| C-1 | 마감은 2026-11-06 17:00(AX 미니과제 제출 마감)이다 |
| C-2 | 모델은 AWS Bedrock으로만 부른다. Anthropic API를 직접 호출하지 않는다 |
| C-3 | 정답·해설 근거는 공식 문서 원문 인용만 인정한다(GR-1) |
