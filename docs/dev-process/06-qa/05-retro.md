## 계획 대비

- 포트: 계획은 8001·5174였다. 10:42에 이 세션 밖에서 띄운 서버가 그 포트를 쓰고 있었고, 멈추는 명령은 권한 분류기에 막혔다. 8002·5175로 바꿨다.
- 시험 DB: 계획은 `scratch.db`였다. 11:07에 8001 서버가 같은 DB에 세트를 만들어 시험 중 세트가 닫혔다. 11:10부터 이 시험만 쓰는 `qa06.db`로 바꿨다. 원인은 "같은 DB를 여는 서버 둘"을 위험 표에 적고도 시작 전에 막지 않은 것이다.
- 시험 탭: 11:17에 이 세션 밖에서 닫혔다. 저장소 값으로 상태를 되찾았다.
- 병렬 수정: 계획은 시험 → 발견 보고 → 수정 순서였다. 사용자 지시(11:27)로 화면 수정을 워커가 시험과 동시에 했다. 병합은 시험과 기준 점수 뒤에 했다. 계획 "수정:" 줄에 남겼다.
- TC-11: 사용자 지시는 "브라우저 시험 뒤"였으나 지시를 받기 전(11:22~11:24)에 이미 돌렸다.
- DEF-7: 재확인(3단계) 중에 찾아 코디네이터가 직접 고쳤다. 기준 점수에는 빠져 있다.
- 기록 파일 공동 편집: `01-qa.md`의 개선 제안(IMP-1~IMP-4)과 시각을 이 세션이 아닌 주체가 고쳤다. 내용은 맞았다.
- 확인 대기: 3단계 작업 끝(11:55)과 사용자 확인(12:55) 사이에 1시간이 걸렸다. 마감(13:30) 직전에 `doc`과 `retro`를 서둘러 했다.

## lifecycle 문서 수정안

[skillset-by-lifecycle.md](../skillset-by-lifecycle.md)에 반영할 변경이다. 직접 고치지 않았다.

1. 6행 이유 열: "이 프로젝트는 gstack을 설치하지 않고 `qa/` 절차 파일(`SKILL.md`, `sections/exploratory.md`, `sections/qa-patterns.md`, `references/issue-taxonomy.md`, `templates/qa-report-template.md`)만 따른다. 건강 점수 기준표는 `qa-patterns.md`에 있다. 브라우저는 Orca 내장 브라우저로 대신한다. 06에서 결함 7개 중 4개는 사전 점검이 못 찾은 것이다"를 더한다. 근거: 이 회고 "이 단계에서 더한 기준".
2. "이 프로젝트의 선택" 범위 줄: "6단계는 시간이 남으면 한다"를 "6단계는 2026-11-06에 했다(5단계와 일부 병렬)"로 고친다. "6단계에 쓸 도구는 그 세션이 고른다"를 지우고 1번 내용을 가리킨다.
3. 6행에 QA 환경 규칙을 더한다: "브라우저 시험은 세션마다 전용 DB 사본과 전용 포트를 쓴다. 시작 전에 포트 주인을 확인한다. 같은 DB를 여는 서버가 둘이면 시험이 섞인다." 근거: 11:07 세트 혼입.
4. 6행에 병렬 방식을 더한다: "화면 수정은 격리 워커가 시험과 동시에 하고, 병합은 시험과 기준 점수 뒤에 한다(개발 서버가 화면을 다시 불러오기 때문)." 근거: 02-fix.md. 시험 45분 안에 수정 7개가 끝났다.
5. 6행 보조 열의 "superpowers 검증 스킬"에 "설치 없이 `verification-before-completion` 절차만 따른다. 회귀 테스트는 수정을 되돌리거나 핵심 줄을 바꿔 실패를 본다"를 더한다.
