## 전제 (Phase 3)

전제 공격 점검:

| 점검 | 판단 |
| --- | --- |
| 맞는 문제인가 | 맞다. 실제 문항은 공개 금지, 모의고사 사이트는 정답 미검증·저작권 문제, 공식 샘플은 12개뿐이라 생성이 필요하다 |
| 아무것도 안 하면 | 반복 풀이와 영어 독해 실수 진단 수단이 없다 |
| 이미 있는 것 | 공식 docs MCP, 학습 노트, 공식 문서 예시 코드, 실습 저장소. 새로 만들 것은 엔진과 매핑 |
| 배포 | MVP는 본인이 로컬에서 쓴다 |

처음 제시한 전제 2(후보 CCA-F)와 전제 5(LangChain은 다음 팩)는 사용자가 뒤집었다. 수정본에 모두 동의했다.

1. 대상 사용자는 LangChain·LangGraph로 LLM 앱을 만드는 한국인 개발자이고, 최종적으로 CCA-F 자격이 필요하다. 첫 사용자는 본인이다.
2. MVP는 LangChain 팩이다. 정답 근거는 LangChain 공식 문서와 API 레퍼런스뿐이다. 코드형 문제는 공식 문서 예시 코드를 먼저 쓰고 실습 `.py`는 보조로 쓴다.
3. 차별점은 영·한 구절 매핑과 오답 원인(독해 실수, 개념 실수) 구분이다. 둘 다 MVP에 들어간다.
4. 생성 문제의 학습 효과는 증명되지 않았다. MVP는 정답 오류율, judge와 실행 결과 불일치율, 본인 정답률 변화로 측정한다.
5. CCA-F 팩은 다음 팩이다. 팩 교체 구조는 만들지 않고, 붙일 때 방해되지 않게만 나눈다. 개념 다리는 CCA-F 팩 때 만든다.
6. CCA-F 시험은 LangChain MVP 이후다. 시험 날짜는 미정이고 2026년 11월 말 응시 예정이다(2026-11-04 기준 약 26일).

## 대안 (Phase 4)

| 안 | 요약 | 노력 | 위험 |
| --- | --- | --- | --- |
| A 최소안 | 배치로 문제 풀(JSON) 사전 생성, 서버 없는 단일 페이지 웹, 기록은 로컬 | M | Low |
| B 이상안 | 엔진/팩 분리, 로컬 API 서버, 이의 제기 재판정, Langfuse 지표, interrupt 검수 | L~XL | Med~High (시험 전 미완료 위험) |
| C 측면안 | A 구조 + MVP 근거 범위를 CCA-F와 겹치는 주제로 한정 + 문제마다 관련 CCA-F 도메인 태그 | M | Low~Med |

추천은 C였다. 26일 안에 LangChain 연습과 CCA-F 개념 예열을 함께 하고, 태그별 정답률을 CCA-F 팩의 첫 약점 데이터로 쓰기 위해서다.

### 선택

**C안 + RAG(day2) 포함.** 사용자가 C안을 고르고 RAG를 범위에 넣도록 수정했다.

- MVP 근거 범위: day2(RAG)와 day3~day7 중 CCA-F와 겹치는 주제. day1(LCEL 기초)은 뺀다.
- RAG는 `candidate_ccaf.md`의 도메인-노트 매핑 표에 없다. RAG 문제의 CCA-F 태그는 "해당 없음"을 허용한다. 맞는 도메인이 있는지는 CCA-F 팩 때 Claude 문서로 확인한다.
- 원래 LangChain 후보 문서의 MVP 근거 범위(day3~day5)보다 넓어진다.
