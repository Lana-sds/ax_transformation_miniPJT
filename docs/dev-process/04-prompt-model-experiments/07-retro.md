### 계획한 도구를 쓰지 않은 이유

lifecycle 4행이 고른 도구는 둘이다. 1순위 pstack `/arena`(변형 지시문 여러 개를 동시에 만들어 좋은 부분을 합치는 절차)와 보조 ouroboros `evolve`(명세를 세대마다 다시 쓰는 반복 루프)다. `/arena`는 설치하지 않고 절차만 따랐다. `evolve`는 쓰지 않았다. 사실 근거는 계획 2장과 4장이다. 두 도구의 README와 SKILL.md는 2026-11-05에 다시 읽었다.

#### pstack `/arena`: 설치하지 않고 절차만 따랐다

설치하지 않은 이유:

| 이유 | 내용 | 근거 |
| --- | --- | --- |
| 설치해도 이 환경에서 돌지 않는 부분이 있다 | 모델 설정(`~/.cursor/rules/pstack-models.mdc`)과 모델 이름(`grok-*`)이 Cursor 기준이다. 교차 Judge(후보를 채점하는 다른 계열 모델) 기본값 `grok-4.7-xhigh-fast`를 이 환경에서 부를 수 없다 | 계획 4장 "pstack 설치 영향" |
| 진행 중에 부를 수 없다 | `/arena`는 `disable-model-invocation: true`다. 모델이 스스로 부르지 못하고 사용자가 슬래시 명령으로 불러야 한다. stage 스킬 run 모드는 도구를 직접 부르며 진행한다 | 같은 곳 |
| 설치 영향을 확인하지 못했다 | 마켓플레이스 추가와 플러그인 설치가 필요하다. 훅과 전역 등록 여부는 미확인이다 | 같은 곳 |
| 절차는 문서만으로 따를 수 있다 | SKILL.md에 6단계(과제 정의, 후보 병렬 실행, 교차 Judge, 기반 고르기, 손으로 합치기, 검증)가 모두 적혀 있다. 이 환경의 서브에이전트로 그대로 했다 | 02-arena.md A~F |

앞으로도 설치하지 않아도 되는 이유:

- 설치로 더 얻는 것은 모델 설정과 교차 Judge 둘이다. 둘 다 이 환경에서 쓸 수 없다. 서브에이전트는 Claude 계열만 쓴다.
- 절차만으로 결과가 나왔다. 후보 4개가 모두 금지 파일을 열지 않았고, 합성 노트를 남겼다. EXP-2 변형은 측정을 거쳐 운영에 반영했다.
- 교차 Judge가 하던 일(변형이 나은지 미리 판정)은 앱 측정이 대신했다. 측정은 실제 파이프라인 지표라서 다른 모델의 의견보다 강한 근거다. EXP-2는 측정으로 채택했고, EXP-1은 측정과 `mandela`로 보류했다.
- 남는 빈자리: 측정 전에 변형을 거르는 단계가 없다. 그래서 EXP-1은 17.73 USD를 쓴 뒤에 보류됐다. 이 빈자리는 설치가 아니라 모델 호출 전 `mandela` 점검으로 메운다(lifecycle 수정안 3).
- 다시 볼 조건: 서브에이전트로 다른 계열 모델을 부를 수 있게 되면 교차 Judge를 붙일 수 있다. 그때 설치를 다시 검토한다.
- 설치와 무관한 교훈: 두 실험 모두 후보 2개가 같은 모양으로 모였다. 모든 후보가 같은 과제 정의를 받는 것이 절차 규칙이라 생긴 일이다. 설치해도 바뀌지 않는다.

#### ouroboros `evolve`: 쓰지 않았다

쓰지 않은 이유:

| 이유 | 내용 | 근거 |
| --- | --- | --- |
| 하는 일이 다르다 | README는 Seed(수용 기준을 적은 명세)의 온톨로지(개념 구조)를 세대마다 바꾸고, 세대 사이 유사도 0.95 이상에서 멈춘다고 설명한다(최대 30세대). 프롬프트를 바꾸거나 A/B를 한다는 설명은 없다 | 계획 2장 "고르지 않은 도구" |
| 이 앱의 지표를 재지 않는다 | 이 단계의 질문은 "지시문을 바꾸면 앱의 지표(첫 시도 `quote_match`, 결함 검출 수, 비용)가 나아지는가"다. 이 답은 앱 파이프라인을 실제로 돌려야 나온다. `evolve`는 앱의 생성·Judge 파이프라인을 돌리지 않는다 | 같은 곳 |
| 계획 도구 하나 규칙 | "이 프로젝트의 선택" 절은 계획 단계를 가진 도구(gstack, superpowers, ouroboros)를 하나만 쓰게 한다. 진행은 이미 stage 스킬과 계획 파일이 맡는다 | skillset-by-lifecycle.md |

앞으로도 쓰지 않아도 되는 이유:

- 이 단계의 질문에는 앱 하네스(`quiz experiment judge`, `quiz experiment summary`, `quiz generate --slots`)가 답한다. 이번에 실험 4회와 생성 배치 3개로 판정을 냈다.
- 이 단계의 반복은 "변형 → Bedrock 측정"이다. 한 바퀴마다 실제 비용이 든다(EXP-1 17.73 USD, EXP-2 3.72 USD). 반복 횟수는 사람이 비용을 보고 정해야 한다. 이번에도 상한 30 USD 때문에 두 번 멈추고 범위를 줄였다. 무인 반복 루프와 맞지 않는다.
- 과제 범위는 5단계까지다. 5단계는 같은 ouroboros의 `evaluate`가 1순위다. lifecycle 문서는 `evaluate`도 앱 응답 품질을 재지 않는다고 적는다. 남은 범위에 `evolve`가 맡을 일이 없다.
- 다시 볼 조건: Seed를 고쳐 가며 코드를 다시 만드는 작업이 생길 때. 이 과제 범위에는 없다.

## 계획 대비
