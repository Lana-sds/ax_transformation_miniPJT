### T2.3 재생성 루프, T2.6 dedupe

- 테스트를 먼저 썼고 인자 오류로 실패를 본 뒤 구현했다(`tests/test_pipeline_loop.py`, 10개). 커밋 `59c21f7`. 전체 158개 통과.
- 그래프: `generate → judge → (코드형) execute → gates → dedupe → record`. `record`가 판정하고, 재생성이면 `feedback → generate`로 돈다.

### T2.7 배치 CLI

- 테스트를 먼저 썼고 import 실패를 본 뒤 구현했다(`tests/test_batch.py`, 7개). 커밋 `e8313aa`.
- `generate --plan pilot|pool [--count N]` 또는 `generate --resume <batch_id>`. 둘 중 하나는 꼭 준다.
- 재개는 `batch_slots`의 (버킷, 주제, 형식, 유형)으로 허용 목록에서 슬롯을 다시 만든다(`slots.slot_for`). 계획 종류와 `--count`를 저장하지 않아도 된다.
- 슬롯 하나가 예외로 멈춰도 배치는 나머지를 돈다. 모든 슬롯이 끝나야 `finished_at`을 채운다. CLI는 남은 슬롯이 있으면 재개 명령을 출력하고 1로 끝난다.
- M0 임시 슬롯 경로(`m0_slots`)를 없앴다. `CLAUDE.md` 명령 표와 `m0-smoke.md` 3단계를 `--plan pool --count 1`로 고쳤다. 이제 그 슬롯은 rag 단답이다.
- 확인: 6슬롯 pilot에서 3번째 생성 호출부터 예외를 내 2슬롯만 끝낸 뒤 `--resume`하면 남은 4슬롯만 돌고 끝난 2슬롯의 `updated_at`은 그대로다. 중단은 예외로 흉내 냈다. 실제 모델 배치를 끊는 확인은 생성 모델 한도 때문에 하지 않았다.
- 동시 실행 2개에서 dedupe 비교 대상은 슬롯 시작 때 읽는다. 같은 버킷 두 슬롯이 동시에 돌면 서로를 보지 못한다. 미확인 위험으로 남긴다.

- 확인 (1) 프롬프트 문구 테스트, (2) 가짜 Judge 두 항목 false → `judge_fail:distractors_plausible`, `judge_fail:no_cue` 통과.
