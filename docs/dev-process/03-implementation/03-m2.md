- 테스트를 먼저 썼고 5개 실패를 본 뒤 구현했다(`tests/test_judge.py`, 13개). 커밋 `8c52956`.

### T2.3 재생성 루프, T2.6 dedupe

- 테스트를 먼저 썼고 인자 오류로 실패를 본 뒤 구현했다(`tests/test_pipeline_loop.py`, 10개). 커밋 `59c21f7`. 전체 158개 통과.
- 그래프: `generate → judge → (코드형) execute → gates → dedupe → record`. `record`가 판정하고, 재생성이면 `feedback → generate`로 돈다.
- 시도별 값은 상태의 `attempts`(누적 리스트)에 남긴다. `process_slot`이 끝난 뒤 문제 1행과 시도 행을 쓴다. 토큰은 시도마다 0부터 센다.
- `dedupe` 비교 대상은 슬롯 시작 때 DB에서 읽은 같은 버킷 `passed` 문제다.
- 확인: 항상 실패하는 가짜 게이트로 시도 4행(0~3), `dropped`/`regen_exhausted`, `regen_count`=3. 같은 quote 문제 두 번째는 `duplicate`, 시도 1행, 생성 호출 없음.
