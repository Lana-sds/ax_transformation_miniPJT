## 도구별 평가

요약: 이 단계는 구현용 스킬을 쓰지 않았다. lifecycle 1순위 superpowers는 설치하지 않았고(계획 결정 1), 계획한 보조 스킬 `readchk`도 호출 기록이 없다. 구현은 TASKS.md 작업 순서를 따라 프로젝트에 내장된 stage 스킬(`.claude/skills/stage`) run 모드로 진행했다. TDD는 `CLAUDE.md` 작업 규칙으로, 병렬 실행은 stage 스킬 run 3번 절차의 격리 worktree 서브에이전트로 했다. 외부 도구는 문서 스냅샷 수집에 쓴 MCP 2개뿐이다.

## 계획 대비

- 일정: 계획 위험 표는 작업 47개를 약 24시간으로 잡았다. 실제로는 작업 51개를 329분에 끝냈다. 마감보다 약 26시간 일찍 끝났다.
- 작업 수: 사용자 요청으로 T2.10, T2.11, T4.7, T4.8, T4.9를 더했다. T5.6은 감사 `pass`라 필요 없었다. T7.1은 면제다. 체크한 작업은 51개다.
- 순서: 사용자 지시로 M4 워커를 M3 파일럿 전에 띄웠다. M5 T5.2·T5.3을 T4.1 보충 배치와 함께 했다. T7.2를 M6 중에 했다. 계획 "진행 순서"는 묶음을 순서대로 둔다. 실제로는 M2~M5가 시각이 겹쳤다.
- 계획 위험 표에 없던 위험: Bedrock 일일 토큰 한도. 생성 모델이 `Too many tokens per day`에 걸렸다. 한도는 소스 리전과 추론 프로필마다 따로였다. 사용자에게 두 번 묻고 프로필 전환과 리전 전환을 구현했다(design.md 6.0, 7.0). 원인은 계획이 "자격 증명"과 "단가"만 위험으로 보고 한도를 보지 않은 것이다.
- 파일럿 추정: 파일럿 passed 5/6으로 풀 passed 약 50개를 추정했다. 풀 배치는 36/60이었다. 원인은 세 가지다. pool 계획이 파일럿과 같은 첫 주제부터 배정해 `duplicate`가 났다. 샌드박스에 `numpy`, `langchain-text-splitters`가 없었다. 인용의 마크다운 링크·코드 펜스 때문에 `quote_mismatch`가 났다. 보충 배치 `--plan fill`은 설계 6.1에 문장만 있고 구현이 없어 T4.1 중에 만들었다.
- 생성 비용: `baseline.json` 배치 15개 합이 36.75 USD, 입력 9,908,263, 출력 461,654 토큰이다. 풀 배치 18.60 USD 뒤 보충 11회에 16.43 USD가 더 들었다. M0 배치와 교차 풀이 비용은 단가가 없어 미확인이다.
- TDD: 계획 결정 1은 "테스트를 먼저 쓰고 실패를 본 뒤 구현"을 직접 지키게 했다. UI 작업 4개(T4.5, T4.6, T5.3, T4.9)는 컴포넌트 테스트 도구가 없어 테스트를 먼저 쓰지 못했다. T4.7·T4.8은 순수 함수를 `node --test`로 시험했다.

## lifecycle 문서 수정안

[skillset-by-lifecycle.md](../skillset-by-lifecycle.md)는 직접 고치지 않았다. 사용자가 반영 여부를 정한다.

1. "이 프로젝트의 선택" 절의 "기본: superpowers 하나로 시작한다"를 바꾼다: "3단계는 구현 스킬 없이 TASKS.md 작업 순서와 프로젝트 내장 stage 스킬 run 모드로 했다. TDD는 `CLAUDE.md` 작업 규칙으로, 병렬은 격리 worktree 서브에이전트로 했다. 격리 worktree는 기본 브랜치에서 갈라지므로 워커는 코디네이터 HEAD로 맞춘 뒤 시작한다." "3. 구현" 행의 1순위 superpowers는 이 프로젝트에서 쓰지 않았다고 적는다. 근거: 작업 51개 완료, 워커 5개 병합 충돌 0건. superpowers와의 비교 근거는 없다.
2. "3. 구현" 행 이유 열에 한 줄 추가: "UI 작업은 컴포넌트 테스트 도구를 0단계에서 정한다. 없으면 테스트를 먼저 쓸 수 없다." 근거: UI 작업 4개가 TDD를 못 했다.
3. "이 도구들이 덮지 못하는 영역"의 "비용 제한, 레이트리밋" 줄에 덧붙인다: "Bedrock 일일 토큰 한도는 소스 리전과 추론 프로필마다 따로 걸린다. 대량 생성 전에 전환 순서를 정한다." 근거: 03-m2.md "리전 전환, Judge 전환".
