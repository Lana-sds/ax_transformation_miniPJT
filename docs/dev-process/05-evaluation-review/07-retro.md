## 쉬운 설명

05는 "만든 앱이 약속대로 되는가"를 증거로 확인하고 숨은 버그를 찾는 단계였다. 네 가지 도구를 썼다.

- 수용 기준 평가 도구(ouroboros `evaluate`): 테스트·빌드·lint를 돌리고 기준 9개를 하나씩 판정했다. 03과 같은 결론(모두 통과)을 냈고, 새 버그는 찾지 못했다.
- 적대적 리뷰 절차(pstack `/interrogate`, 설치하지 않고 절차만): 서브에이전트 3명이 앱을 깨 보게 했다. 실제로 돌려서 증명한 발견 17건이 나왔고, 심각도 "높음" 5개가 모두 여기서 나왔다.
- 평가 누수 점검(paperthin `mandela`): 평가를 시작하기 전에 "평가 방법이 스스로를 확인만 하는가"를 맥락 없는 점검자가 봤다. 보완안 7개를 냈고 사용자가 모두 반영했다.
- 무맥락 재독(paperthin `shower`): 보고서 초안을 처음 보는 사람처럼 읽고 막히는 곳 15개를 짚었다. 15개 모두 고쳤다.

결론: 이 프로젝트에서 버그를 찾은 것은 적대적 리뷰였다. 평가 도구는 "기준을 충족한다"는 증명과 기계 검사를 맡았다. lifecycle 문서의 5행이 평가 도구를 1순위, 적대적 리뷰를 보조로 둔 것은 이번 결과와 맞지 않는다(아래 수정안 1).

### 계획한 도구를 쓰지 않은 이유

lifecycle 5행의 1순위와 보조는 6개다. 쓴 것은 `evaluate`, `/interrogate`(절차만), `mandela`, `shower` 4개다. 사실 근거는 계획 2장과 4장이다. README와 SKILL.md는 2026-11-06에 다시 읽었다.

#### pstack `/interrogate`: 설치하지 않고 절차만 따랐다

| 이유 | 내용 | 근거 |
| --- | --- | --- |
| 진행 중에 부를 수 없다 | `disable-model-invocation: true`다. stage 스킬 run 모드는 도구를 직접 부르며 진행한다 | 계획 4장 "pstack 설치 영향" |
| 설치본의 공격자 모델 설정을 쓸 수 없다 | arena 설정(`interrogate reviewers` 줄, Cursor 모델 이름)을 읽는다. 이 환경 서브에이전트는 Claude 계열뿐이다 | 같은 곳 |
| 절차는 문서만으로 따를 수 있다 | 의도 재진술, 공격자 병렬 실행, 실행 증거 요구, 코디네이터 재현 검증, 원인별 합치기가 SKILL.md에 있다. 그대로 했다 | 03-interrogate.md |

앞으로도 설치하지 않아도 되는 이유:

- 설치로 더 얻는 것은 공격자마다 다른 모델을 쓰는 설정이다. 이 환경에서는 쓸 수 없다.
- 같은 계열 공격자의 사각지대는 영역 나누기와 예시 빼기로 줄였다. 공격자 사이 겹침이 0건이었다. 공격자 B는 자기 영역 밖에서 "높음"(F-4)을 찾았다.
- 다시 볼 조건: 서브에이전트로 다른 계열 모델을 부를 수 있게 되면 다시 검토한다.

#### gstack `/review`, paperthin `factchk`, `sip`: 쓰지 않았다

| 도구 | 이유 | 빠진 것이 드러났는가 |
| --- | --- | --- |
| gstack `/review` | "이 프로젝트의 선택" 절이 gstack을 뺐다(Windows 마찰, 배포 중심) | 아니오. 코드 리뷰 역할은 공격자 3명이 실행 증거로 맡았다 |
| `factchk` | 이 단계의 주장은 실행 증거로 확인한다. 외부 사실 주장이 적다 | 아니오. 외부 사실 주장(교차 풀이 단가)은 확인하지 못해 "미확인"으로 남겼다. `factchk`로도 단가 파일이 없는 것은 바뀌지 않는다 |
| `sip` | `shower`와 역할이 겹친다 | 아니오. `shower`가 막힘 15개를 찾았다 |
